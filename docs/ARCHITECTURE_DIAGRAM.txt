================================================================================
                       METRICS VISIBILITY STACK
================================================================================

LAYER 1: Metric Definition (MeterBinder)
  └─ 2 MeterBinders × 9 métricas = 9 counter/timer/gauge definitions

LAYER 2: Metric Collection (MeterRegistry)
  └─ Global registry stores live metric values
  └─ Updates em cada operação (increment, record)

LAYER 3: Metric Export (Micrometer Prometheus Registry)
  └─ Converts MeterRegistry to Prometheus text format
  └─ Exposed via /actuator/prometheus

LAYER 4: Collection (Prometheus Server)
  └─ Scrapes /actuator/prometheus a cada 15 segundos
  └─ Armazena séries temporais (TSDB)

LAYER 5: Visualization (Grafana Dashboard)
  └─ Query Prometheus via PromQL
  └─ Exibe gráficos, alertas, dashboards

LAYER 6: Alerting (Alertmanager)
  └─ Define SLOs/thresholds
  └─ Notifica via email, Slack, PagerDuty

                      VIRTUAL vs PLATFORM THREADS
================================================================================

┌──────────────────────────────┬──────────────────────────────┐
│    VIRTUAL THREADS           │    PLATFORM THREADS          │
│    (JEP 444 - Java 21)      │    (Traditional Threading)    │
├──────────────────────────────┼──────────────────────────────┤
│ 📊 METRICS                   │ 📊 METRICS                   │
│                              │                              │
│ threads.virtual.active: 45   │ threads.virtual.active: 0    │
│ threads.platform.active: 10  │ threads.platform.active: 100 │
│                              │                              │
│ 📈 PERFORMANCE               │ 📈 PERFORMANCE               │
│                              │                              │
│ Throughput (5 req/s)         │ Throughput (2 req/s) ⚠️     │
│ orders.create.duration P95: 245ms │ P95: 380ms ⚠️           │
│                              │                              │
│ Memory: Low (μm stack)       │ Memory: High (1MB per thread)│
│                              │                              │
│ Latency: Low                 │ Latency: High (thread pool)  │
│ I/O Blocking: Efficient ✅   │ I/O Blocking: Wasteful ⚠️    │
│                              │                              │
└──────────────────────────────┴──────────────────────────────┘

Demonstração via Métricas:
  - Criar 50 pedidos com VT: ~10 segundos ✅
  - Criar 50 pedidos com PT: ~25 segundos ⚠️

Ver diferença:
  1. Anote threads.virtual.active com VT
  2. Desabilitar VT em application.yml
  3. Reiniciar e anote threads.platform.active
  4. Compare nos gráficos Grafana
